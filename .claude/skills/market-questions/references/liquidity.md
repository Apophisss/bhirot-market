# גמישות השוק — `liquidity`

## מה זה `b`

מנוע השוק (`src/lib/lmsr.ts`) הוא LMSR בינארי. `liquidity` הוא ה-`b` שלו: **קנה המידה בשקלים
שעליו המחיר זז**. הוא לא "כמה כסף יש בשוק" — הוא כמה כסף צריך כדי להזיז אותו.

- `b` **קטן** = שוק דק. ₪100 מקפיצים את המחיר. כיף בשאלה שאף אחד לא נוגע בה, אסון בשאלה
  פופולרית — שחקן אחד קונה ב-₪500 והמחיר כבר לא אומר כלום.
- `b` **גדול** = שוק עבה. המחיר יציב ומייצג הרבה כסף, אבל בשאלה נישתית הוא ייראה תקוע על
  מחיר הפתיחה עד שייסגר.

ברירת המחדל של האתר היא **2000**, וכל שווקי ה-seed משתמשים בה.

## שני המספרים שמחליטים

הכלי מודד את הגמישות **בצד הזול** — הצד שבו ₪100 קונים הכי הרבה מניות, ולכן הצד שבו המחיר
זז הכי מהר. בשוק של 12% זה צד ה"כן"; בשוק של 88% זה צד ה"לא".

| מדד | יעד | למה |
|---|---|---|
| הימור רגיל של ₪100 (1% מהיתרה ההתחלתית) | 1–8 נקודות אחוז | פחות מ-1 והמחיר נראה קפוא; יותר מ-8 והשוק נראה שבור |
| הזמנה של ₪1,000 (10% מהיתרה) | עד 40 נקודות אחוז | מעבר לזה שחקן אחד משתלט על המחיר |

הערכים האלה מוגדרים ב-`src/lib/elasticity.ts` ונבדקים ב-`scripts/test-elasticity.ts`.

## הכלי

```bash
npm run markets:liquidity -- --p 0.3                 # השוואת הסולם 500/1000/2000/4000/8000
npm run markets:liquidity -- --p 0.3 --traffic hot   # לשאלה שתוביל את הדף הראשי
npm run markets:liquidity -- --p 0.3 --traffic niche # לשאלה נישתית קצרה
npm run markets:liquidity -- --p 0.3 --b 2000        # פירוט מלא לערך אחד
npm run markets:liquidity -- --slug <slug>           # שוק קיים
npm run markets:liquidity -- --audit                 # כל השווקים הפתוחים
```

איך קוראים את טבלת ההשוואה:

```
  b        ₪10      ₪100     ₪500     ₪1000    5pp costs  99% cap   verdict
  2000     30.3%    33.4%    45.5%    57.5%    ₪365       ₪8497     ✓ ₪100 → 3.4pp, ₪1000 → 27.5pp
```

- ארבע העמודות הראשונות: לאן המחיר מגיע אחרי קנייה בסכום הזה בצד הזול.
- `5pp costs`: כמה שקלים צריך כדי להזיז 5 נקודות אחוז.
- `99% cap`: הסכום המקסימלי שהשוק בכלל מקבל בצד הזה לפני שהוא נוגע ברצועת 1%–99%.
  אם המספר הזה קטן מ-₪2,000 בערך, שחקן אחד יכול לרוקן את השוק בהזמנה אחת.
- `verdict`: `✓` = בחלון הבריא, `·` = `thin`/`thick`/`borderline` עם ההסבר.

## ההחלטה

| מצב | `liquidity` |
|---|---|
| שאלה רגילה | **2000** |
| `featured: true`, שאלה שתוביל את הדף הראשי, סיפור גדול | 4000 |
| שאלה נישתית שנסגרת ב-48 שעות, מעט סוחרים | 1000 |
| הכלי החזיר `thin` או `thick` ל-2000 | מה שהוא ממליץ |
| כל דבר אחר | 2000, ותסבירו ב-commit למה לא |

הכלי כבר מעדיף את 2000 בכל פעם שהוא בריא — `--traffic` רק מזיז שלב אחד בסולם. אין סיבה
לרדת מתחת ל-500 או לעלות מעל 8000 בלוח בגודל הנוכחי.

## למה זה נקבע פעם אחת

`upsertMarkets` ב-`src/lib/sync.ts` כותב `liquidity`, `qYes`, `qNo` ו-`probability` **רק
כששוק נוצר**. בעדכון של שוק קיים הוא מסנכרן שדות עריכה בלבד (כותרת, תיאור, קריטריונים,
מקורות, `closesAt`, `featured`).

לכן שינוי של `liquidity` או `initialProbability` בשוק שכבר עלה **לא משנה כלום באתר** — הוא רק
יוצר פער בין ה-JSON למסד הנתונים. `AGENT.md` אוסר את זה מפורשות, וזו הסיבה הטכנית.

זה גם מה שהופך את ההחלטה הזו לחד־פעמית: **בוחרים לפני ה-commit הראשון.** אם שוק פתוח יצא
מהחלון הבריא (ה-audit יגיד), נותנים לו לחיות — התיקון היחיד שמותר הוא בשאלה הבאה.
