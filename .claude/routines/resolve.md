# רוטינת ההכרעות — מה עושים בכל ריצה

הרוטינה הזאת רצה **חמש פעמים ביום, רק בשעות היום בישראל**, בסשן חדש בריפו הזה. היא הצד המתוזמן
של הצינור שמתואר בסקיל `.claude/skills/market-resolutions` — קראו אותו, הוא אומר איך מחקר נראה
ומה נחשב ראיה. הקובץ הזה אומר רק מה ריצה מתוזמנת עושה, ומה היא אסורה לעשות.

הקרון הוא `0 7,10,13,16,18 * * *` ב-UTC. השעות נבחרו כך שהן נשארות בתוך 09:00–21:00 שעון ישראל
**בשני צידי שינוי השעון**, בלי לתחזק את הקרון פעמיים בשנה:

| | ריצות בשעון ישראל |
|---|---|
| שעון קיץ (UTC+3, עד 25.10.2026) | 10:00 · 13:00 · 16:00 · 19:00 · 21:00 |
| שעון חורף (UTC+2) | 09:00 · 12:00 · 15:00 · 18:00 · 20:00 |

**בלילה אין ריצות.** שוק שנסגר ב-23:59 ייבדק בריצה הראשונה של הבוקר. זה מכוון: אין מי שיאשר
בשלוש לפנות בוקר, והדיווח שמכריע שאלה של חצות מתפרסם ממילא בבוקר.

## הכלל שמעל הכל

**הרוטינה לא מכריעה. היא מציעה.** אף ריצה מתוזמנת לא מריצה `approve`, `apply` או `publish` על דעת
עצמה, גם אם הראיה חד־משמעית ואפילו אם ריצה קודמת אישרה שאלה דומה. היא עוצרת על הדוח וממתינה
לאדם. אישור מגיע רק כאמירה מפורשת של המשתמש בשיחה, על הריצה הזאת.

## א. הריצה המתוזמנת

```bash
git pull --ff-only
npm ci --no-audit --no-fund        # אם node_modules חסר
npm run resolve -- propose --grace 1
```

`--grace 1` משאיר בחוץ שוק שנסגר בשעה האחרונה: הדיווח שמכריע אותו בדרך כלל עוד לא פורסם.

1. **אין חוב הכרעות** (`propose` אומר "אין חוב הכרעות") — סיימו כאן. בלי commit, בלי הודעה
   למשתמש, בלי לפתוח ריצה ריקה. ריצה שקטה היא ריצה תקינה.
2. **יש חוב** — חקרו כל שוק לפי הסקיל: הריצו את החיפוש שהשאלה הבטיחה, פתחו ב-WebFetch את העמוד
   שהוא מחזיר, והעתיקו ממנו ציטוט. מלאו `verdict`, `confidence`, `note`, `evidence`,
   `searchedFor`, `researchedAt` בקובץ הריצה.
   שוק שלא נסגר בראיה — השאירו בלי `verdict` ורשמו ב-`note` מה חסר. אל תמציאו ראיה, ואל תכריעו
   "לפי ההיגיון".
3. ```bash
   npm run resolve -- report
   ```
   ואז commit ו-push של קובץ הריצה (לא של `data/markets.json` — הוא עוד לא השתנה):
   ```bash
   git add data/resolutions
   git commit -m "resolutions: ריצה <runId> — N הצעות ממתינות לאישור"
   git push -u origin <branch>
   ```
4. **שלחו את הדוח למשתמש** (`SendUserFile` על ה-HTML) עם סיכום של שתי שורות: כמה שווקים, איך
   מתחלקות ההצעות, ומה חסום או דורש עין. **אל תסכמו במקומו "הכל תקין"** — הדוח קיים כדי שהוא
   יראה את הראיה. אמרו במפורש שממתינים לאישור שלו, ועצרו.

## ב. כשהמשתמש מאשר

זה קורה באותה שיחה, אחרי שהוא קרא את הדוח. "מאשר", "אשר הכל", "אשר את א' ו-ב', תדחה את ג'".

```bash
npm run resolve -- approve --by "<שמו של המאשר>" --all        # או --only / --reject
npm run resolve -- apply
npm run markets:validate && npm run markets:audit
git add data/markets.json data/resolutions
git commit -m "markets: הוכרעו N שווקים"
git push -u origin <branch>
npm run resolve -- publish                                     # אם יש SITE_URL ו-ADMIN_TOKEN
```

- `--by` הוא שם המאשר, לא "routine" ולא "claude".
- אישור חלקי הוא אישור: מה שלא אושר נשאר בקובץ הריצה וממתין. אל תשכנעו.
- אין `SITE_URL`/`ADMIN_TOKEN` בסביבה? `apply` וה-commit עדיין רצים, והשינוי יעלה לאתר עם הפריסה
  הבאה של `main`. אמרו את זה למשתמש במקום לדלג בשקט.
- בסוף: כמה הוכרעו ואיך, מה נדחה, מה נשאר בלי ראיה, ומה השרת אישר.

## ג. מה ריצה מתוזמנת לא עושה

- לא מאשרת, לא כותבת ל-`data/markets.json`, ולא מפרסמת בלי אישור מפורש בשיחה.
- לא מפרשת "כן" על נושא אחר, ולא אישור מריצה קודמת, כאישור להכרעות שלפניה.
- לא מוסיפה שאלות חדשות — זו רוטינה אחרת (`AGENT.md` + `.claude/skills/market-questions`).
- לא נוגעת ב-`initialProbability`, `liquidity`, `slug` או בניסוח של שוק קיים.
- לא מודיעה כשאין מה לדווח.

## ד. תקלות

- ריצה קודמת שנשארה עם הצעות שלא אושרו: `propose` יתריע. אל תפתחו לה כפילות — המשיכו את הריצה
  הישנה (`npm run resolve -- status`) והזכירו למשתמש שהיא ממתינה.
- `publish` נכשל או שוק נשאר `open` בשרת: הרשומה מסומנת `failed`. `publish` ניתן להרצה חוזרת,
  ומה שכבר פורסם לא נשלח פעמיים.
- `apply` מסרב בגלל שינוי בשאלה או באישור: זה תקין ולא באג. הריצו `propose` מחדש והביאו את הדוח
  לאישור שוב.
