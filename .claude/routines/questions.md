# רוטינת השאלות — מה עושים בכל ריצה

הרוטינה הזאת רצה **חמש פעמים ביום, בשעות שבהן החדשות בישראל באמת זזות**, בסשן חדש בריפו הזה.
היא הצד המתוזמן של הצינור שמתואר ב-`AGENT.md` ובסקיל `.claude/skills/market-questions` —
קראו אותם, הם אומרים איך מוצאים שאלה, איך מוודאים שהיא ניתנת להכרעה, ואיך מתמחרים אותה.
הקובץ הזה אומר רק מה ריצה מתוזמנת עושה, ומה היא אסורה לעשות.

הקרון הוא `0 6,9,12,15,19 * * *` ב-UTC. השעות נבחרו סביב הקצב של יום חדשות ישראלי, ונשארות
הגיוניות **בשני צידי שינוי השעון** בלי לתחזק את הקרון פעמיים בשנה:

| | ריצות בשעון ישראל |
|---|---|
| שעון קיץ (UTC+3, עד 25.10.2026) | 09:00 · 12:00 · 15:00 · 18:00 · 22:00 |
| שעון חורף (UTC+2) | 08:00 · 11:00 · 14:00 · 17:00 · 21:00 |

הריצה של הערב היא המכוונת ביותר: מוצאי שבת הוא ליל הסקרים של חדשות 12 ו-13, וסקר שמתפרסם
ב-20:00 שווה שאלה ב-22:00 — לא למחרת בבוקר.

הריצות משתלבות בין ריצות ההכרעה (`0 7,10,13,16,18` ב-UTC, `.claude/routines/resolve.md`), כך
ששתי הרוטינות לא נוגעות ב-`data/markets.json` באותה שעה.

## הכלל שמעל הכל

**הרוטינה הזאת כן מפרסמת בעצמה.** להוסיף שאלה זה מהלך הפיך — שוק שהתברר כשגוי מבוטל והכסף חוזר —
ולכן אין כאן שער אישור אנושי. בדיוק בגלל זה כל שאר השערים מחייבים: תשעת שערי הווידוא בסקיל,
`npm run markets:validate`, `npm run markets:audit` ו-`npm test` רצים לפני כל פרסום, ובלי שכולם
ירוקים לא מפרסמים כלום.

**ומה שהיא לא עושה: היא לא מכריעה שווקים.** הכרעה משלמת כסף ואי אפשר לבטל אותה. גם אם ראיתם
בחיפוש שהאירוע קרה — אל תיגעו ב-`status`, ב-`resolution` וב-`resolutionNote` של שום שוק. זו
הרוטינה השנייה, והיא עוצרת לאישור אנושי.

## א. הריצה המתוזמנת

```bash
git pull --ff-only
npm ci --no-audit --no-fund        # אם node_modules חסר
npm run markets:audit              # מה כבר יש, איפה חורים, ומה החום החדשותי של הלוח עכשיו
```

1. **קראו את ה-audit לפני שאתם מחפשים.** שני מקטעים מכוונים את הריצה: `topicality` אומר אם יש
   בכלל שאלה חמה על הלוח כרגע (אם אין — זה בדיוק מה שאתם הולכים לחפש), ו-`calibration` אומר אם
   האחוזים שלכם היו אופטימיים מדי בעבר. חוב ההכרעות שמוצג שם **אינו העבודה שלכם** — רשמו אותו
   לעצמכם ועברו הלאה.
2. **הצעות ממשתמשים קודם.** אם יש `SITE_URL` ו-`ADMIN_TOKEN` בסביבה, עברו על התיבה
   (`AGENT.md` → "הצעות שאלה שהגיעו ממשתמשים") לפני החיפוש בחדשות. הצעה טובה חוסכת ריצה שלמה,
   והמציע רואה שענו לו.
3. **חקרו** את 24–72 השעות האחרונות ב-WebSearch/WebFetch, בעברית ובאנגלית, בשני המסלולים
   שהסקיל מגדיר: מה קרה (סקר, מיזוג, עתירה, ריאיון, פיצוץ קואליציוני) ומה עומד לקרות (יומן
   הכנסת, ישיבות ממשלה, דיוני בג"ץ, דדליינים של חוק הבחירות).
4. **כתבו 2–6 שאלות** שעברו את תשעת השערים, לפחות שליש מהן נסגרות תוך 24–72 שעות. לכל שאלה:
   `initialProbability` לפי `references/pricing.md`, `liquidity` לפי `npm run markets:liquidity`,
   `appeal` ו-`topicality` לפי הסעיף הבא.
5. **הרכיבו ומזגו:**
   ```bash
   npm run markets:duplicates -- --batch /tmp/batch.json   # שער 6 — לפני המיזוג
   npx tsx scripts/merge-markets.ts /tmp/batch.json --note "<תקציר בעברית של מה נוסף>"
   npm run people:fetch          # רק אם נוספו אנשים
   npm run markets:validate      # סכמה — חייב לעבור
   npm run markets:audit         # בריאות הלוח — תקנו כל ✗, שקלו כל ⚠
   npm test                      # אינווריאנטות של מנוע השוק
   ```
   דחייה של `merge-markets.ts` (slug כפול, כותרת דומה מדי, `closesAt` קרוב מדי) היא תשובה, לא
   תקלה. אל תעקפו אותה בשינוי מילה בכותרת. שאלה שנדחתה כ-`looks like ...` היא שאלה ששכחתם
   לקרוא את השכנה שלה: פתחו את ה-`resolutionCriteria` שלה, ואז או שהשאלה יורדת, או שהיא מקבלת
   `notDuplicateOf` עם משפט שאומר מה מכריע כל אחת מהן.
6. **commit ו-push לענף משלכם, ואז PR:**
   ```bash
   git checkout -b claude/questions-<YYYY-MM-DD-HHMM>
   git add data/markets.json data/people.json
   git commit -m "markets: <תקציר קצר בעברית>"
   git push -u origin claude/questions-<YYYY-MM-DD-HHMM>
   ```
   ואז PR ל-main (draft), עם רשימת השאלות שנוספו, הדירוגים שנתתם והנימוק לכל `topicality` של 4+.
   **אל תדחפו ישירות ל-main.**
7. **פרסמו לאתר החי** — זה מה שהופך את הריצה ל"אוטומטית". רק אם יש `SITE_URL` ו-`ADMIN_TOKEN`:
   ```bash
   node -e '
   const f=require("./data/markets.json");
   fetch(process.env.SITE_URL+"/api/admin/markets",{method:"POST",headers:{"content-type":"application/json",authorization:"Bearer "+process.env.ADMIN_TOKEN},body:JSON.stringify({markets:f.markets,note:f.lastUpdateNote,source:"routine"})}).then(r=>r.json()).then(j=>console.log(JSON.stringify(j)))'
   ```
   אין הרשאות בסביבה? זו לא תקלה: השאלות יעלו עם המיזוג של ה-PR והפריסה הבאה של `main`. אמרו
   את זה במפורש במקום לדלג בשקט.
8. **דווחו בשתי שורות**: אילו שאלות נוספו (כותרת, מועד סגירה, אחוז פתיחה, `appeal`/`topicality`),
   מה נדחה ולמה, ומה השרת החזיר.

## ב. הדירוגים — הלב של הריצה הזאת

הרוטינה מוסיפה שאלה שאף אחד עוד לא ראה. כל האותות שמנוע ההמלצות מודד — כמה כסף עבר, כמה אנשים
ענו, כמה תגובות — שווים אפס בשעה הראשונה שלה. שני הדירוגים שאתם נותנים הם **כל מה שיש לשאלה
ביום הראשון**, ולכן הם לא קישוט:

- **`appeal` (1–5)** — כמה השאלה מגניבה. נשאר נכון כל עוד השאלה פתוחה. לכל היותר 5 אחד בריצה.
- **`topicality` (1–5)** — כמה השאלה צמודה לחדשות של **עכשיו**. נמדד מול `createdAt` ודועך ממנו:
  5 טרי הוא האיבר הכי כבד בכל הניקוד, מחציתו נשארת אחרי 36 שעות, ותוך שבוע הוא אפס.

הכללים המעשיים:

- דרגו `topicality` **מול רגע הכתיבה, לא מול חשיבות הנושא.** משפט נתניהו חשוב תמיד; שאלה עליו
  שווה 5 רק אם משהו קרה בו בשעות האחרונות.
- **5 = מבזק של השעות האחרונות**, ולכל היותר אחד בריצה. **4 = כותרת של היום.** שאלה שנולדה
  מהיומן ולא מהחדשות (מועד קבוע, דדליין חוקי) היא 1–2, וזה בסדר גמור — היא פשוט לא מקבלת קפיצה.
- 5 על אירוע מלפני שבוע הוא שקר שנגמר תוך יום: הוא קונה קפיצה לסיפור שכבר מת, וזו בדיוק החוויה
  שהאתר לא רוצה לתת.
- אם דירגתם את כל הריצה 4–5, המנוע חזר בדיוק למצב שבו אין דירוג. ה-audit מתריע על זה.

## ג. מה ריצה מתוזמנת לא עושה

- לא מכריעה שווקים, לא נוגעת ב-`status`/`resolution`/`resolutionNote`, וגם לא מריצה
  `npm run resolve`. חוב הכרעות שהיא רואה ב-audit — היא רק מזכירה בדיווח.
- לא משנה `initialProbability`, `liquidity` או `slug` של שוק קיים. תיקון ניסוח או מקור בשוק
  קיים — רק אם התגלתה טעות ממש, ובנפרד מהשאלות החדשות.
- לא דוחפת ל-`main` ולא ממזגת PR בעצמה.
- לא ממציאה כתובות. כל URL נפתח ב-WebFetch לפני שהוא נכנס לקובץ.
- לא מוסיפה שאלה "כדי שיהיה". **ריצה בלי חדשות אמיתיות היא ריצה בלי commit ובלי הודעה למשתמש** —
  ריצה שקטה היא ריצה תקינה.
- לא מוסיפה שאלה שכבר קרתה, כפילות של שאלה פתוחה, או שאלה על מוות/בריאות של אדם.

## ד. תקלות

- `markets:validate` או `npm test` נכשלים: אל תפרסמו כלום. תקנו את ה-batch, או זרקו את השאלה
  שנפלה והמשיכו עם השאר.
- `merge-markets.ts` דחה את כל השאלות: זו תשובה — הלוח כבר מכסה את מה שמצאתם. סיימו בלי commit.
- ה-POST לשרת נכשל או החזיר שגיאה: ה-commit וה-PR כבר קיימים, ולכן השאלות יעלו עם הפריסה הבאה.
  דווחו על הכישלון עם גוף התשובה, ואל תנסו לעקוף אותו בכתיבה ישירה למסד.
- ריצה קודמת השאירה ענף פתוח בלי PR: פתחו לו PR לפני שאתם פותחים ענף חדש, כדי ששאלות לא ייעלמו
  בענף נטוש.
